# 侧栏换笔记后沿用旧会话

## 问题

侧栏与 AI 对话页共用聊天 store。原先换笔记只更新 `fileIds` 和顶部文件名，仍沿用同一个 `activeConversationId`；当独立 AI 页停留在 WorkBuddy 时，侧栏还会自动显示最近一个云端会话。当前笔记与会话历史、待确认任务可以因此属于不同会议。

## 客户端修复

- 侧栏创建的会话增加 `contextFileId`，持久化时保留并验证该字段。
- 打开侧栏时核对当前笔记；换笔记后清空显示、输入草稿和待确认卡片，下一次发送创建新的服务端 `sessionId`。
- 同一篇笔记关闭再打开时保留本篇对话。侧栏历史列表只展示本篇笔记的会话。
- 未选中笔记时清空侧栏显示并禁用发送，不展示或发送通用聊天。关闭 A 的侧栏、切换到 B、重新打开时，旧对话、草稿和待确认状态全部清空。
- 请求层不允许将本篇笔记接入其它笔记或通用聊天的旧会话；声明的笔记范围与请求会议 ID 不一致时拒绝发送。
- 点击确认时读取当前真实选中笔记，核对卡片所属会话及原请求会议。缺失、已回答或跨笔记的旧卡片不发起后续请求。
- 旧会话后台事件仍写回它自己的历史，不进入新笔记的侧栏。此前的登录 token 同步、指定会议标记、转写刷新修复继续保留。
