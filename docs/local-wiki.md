# 本地知识库与 Wiki

此实现使用现有 Rust/Tauri 运行时、文件存储和新增的 SQLite 索引；不引入 gbrain、Node/Bun 运行时、LanceDB 或模型权重。参考 `nashsu/llm_wiki` 的来源分析、主题编译与持久任务思路，代码由本项目原生实现。

## 设置与开关联动

设置 → 笔记同步 → 本地知识库，统一显示目录、同步进度、Wiki、AI 授权、可选向量模型与补充来源。独立“会议记忆”设置卡片已移除。

| 操作 | 本地同步 | Wiki |
| --- | --- | --- |
| 开启 Wiki | 自动开启，优先沿用已有目录，否则默认目录 | 开启，先等待全量同步 |
| 关闭 Wiki | 保持开启并继续同步原文 | 停止整理和自动引用，保留页面 |
| 关闭本地同步 | 关闭 | 持久关闭当前及其他账号的 Wiki |
| 再开启本地同步 | 开启 | 保持关闭，由用户单独开启 |
| 更换目录 | 撤销旧请求、迁移、重新同步校验 | 校验完成前不运行 |

联动由 `vault_config_save` / `workbench_configure` 原生接口保证。界面显示原生实际结果；保存失败会显示错误并刷新状态。目录迁移在移动前检查不同内容的同名文件；发生冲突保留两份并拒绝覆盖。迁移失败时处理保持暂停，用户重试目录设置。

Wiki 标记为 Beta，仅在 debug 构建或已开启测试模式时显示。正式模式同时停止原生整理、模型任务、MCP Wiki 工具和聊天自动引用；已下载原文与本地同步保留。重新进入测试模式后仍须通过完整同步校验。

## 下载与完成门槛

1. 使用已验证账号身份绑定知识库，所有来源和状态按 scope 隔离。
2. 全量会议列表不传年份、文件夹或页面筛选；完整分页、检测空缺/重复页。
3. 下载并原子保存转写、时间轴、说话人、大纲、全部已有纪要、待办与录音标记；音频继续按需访问。同步本身不自动启动转写模型。
4. 复用版本一致且 Markdown/结构化资料校验通过的原文；失败可手动重试，重新绑定/重启后恢复下载。
5. 下载后再次枚举，确认列表未发生变化；所有会议详情完整并通过 Markdown 哈希、结构化版本校验，才发布本轮完成状态。
6. 完成状态绑定账号、会议目录、sync round 和 completed round。重启、目录变更、手动重试或账号变更使旧完成状态失效；旧请求的 generation 不能提交结果。
7. 完成后才允许来源分析、向量 API、主题编译、项目回顾和聊天上下文；之后定期核对并增量落盘。

待转写会议可以完整保存为待转写状态；网络/服务错误不会当作成功。下载不需要 AI 授权或模型配置。Wiki 文本生成复用 Lynclaw 的服务与当前对话模型选择；服务或模型不可用时保留原文并显示错误，支持重试。

## 专题、候选与发布

用户创建项目/专题，填写目的与关键问题。AI 对有授权的本地来源逐段判断相关性并提取证据，再编译候选页面。来源分析按专题目的、人工备注、源版本和模型配置缓存；编译输入分批处理，避免静默丢弃长资料。SQLite 保存任务状态、分析回执、可重建文本索引和可选向量。相同输入的完成专题不重复编译；无关新资料不会使已发布页面失效，证据未变化时复用已有编译结果。手动重试可以重新生成候选，已拒绝/已发布的审阅记录持续保留。失败可重试，中断后复用已完成的分析。

候选必须审阅通过才发布。发布时再次验证候选版本、账号/目录/轮次、原文版本、排除设置、逐字引用和音频时间点。来源或人工备注变化使页面待更新；过期页面不进入自动上下文。旧候选、已发布版本及审阅结果保留在历史记录中。

人工备注、纠正、固定和排除设置保存在专题 JSON 中，不被自动编译覆盖。外部编辑 Markdown 会在读取时保留；覆盖前保存旧文本快照。已发布文件在外部修改后须重新审阅，自动上下文会暂停使用它。

聊天引用 Wiki 页面本身，打开页面可继续跳回所有会议原文与可靠音频时间点；原有会议来源读取与上下文 version 1 契约保持兼容。

## 文件与安全存储

- `<vault>/Meetings/<scope>/`：原文 `.md` + `.source.json`。
- `<vault>/Memory/<scope>/wiki/topics.json`：专题定义、候选、发布与审阅历史。
- `wiki/<topic-id>/candidate.md/.json`、`published.md/.json`：可读内容与引用/审阅元数据。
- `wiki/<topic-id>/revisions/`、`reviews/`、`edits/`：版本与覆盖前快照。
- `wiki/index.sqlite`：可重建索引、向量和任务回执。损坏时保留原数据库并重新创建；正式页面不依赖此数据库。
- `wiki/migration-v1/derived.json`：旧会议记忆的首次备份，重复执行不覆盖。旧人工记忆仍可在原有界面编辑，自动聊天引用仅使用已发布且有效的 Wiki 页面。
- 应用数据 `workbench/<scope>/`：同步状态与不含密钥的专用模型/来源配置。
- 文本模型 API 密钥仅由 Lynclaw 管理，桌面不再接收或保存 Wiki 文本密钥。旧文本配置不会继续使用。
- 向量 API 密钥按账号存入原生 secure storage（发布版本使用现有系统钥匙串路径），不写入 vault、SQLite 或正文日志。

文本生成使用现有 Lynclaw 身份校验与模型配置，携带与聊天一致的 `modelOverride`，不从请求正文推断身份。现有 `/api/desktop/synthesize` 扩展 `source_analysis` 与 `topic_compile`，复用服务端模型调用与逐字证据校验；跨服务地址先验证账号和后端绑定。向量模型支持用户填写 OpenAI 兼容 API，HTTP 只允许 localhost，其他地址须 HTTPS。向量不可用时保留关键词检索；未配置向量时不调用向量 API。模型 API 不执行工具或页面中的指令。

## 可选 Gmail 与扩展

Gmail 通过现有多用户 integrations BFF 读取，第三方令牌不进入桌面端。授权请求固定 `gmail.readonly`，白名单仅允许列出线程与读取线程；动作执行令牌绑定账号连接与具体只读动作。原生查询固定最近 90 天，并按邮件时间过滤旧邮件，不下载附件。

Gmail 在会议全量同步之后单独回填，失败记录在补充来源状态中，不改变会议同步完成判定。先在插件社区安装 Gmail 插件，再到「连接」统一授权、添加账号或断开。Wiki 设置仅从已连接账号中选择并开启来源，不再提供授权按钮或账号 ID 输入。多账号不会静默选择其他账号；切换账号、停用插件或关闭来源后，旧邮箱缓存停止参与整理和引用。断开连接前先撤销该邮箱的 Wiki 来源。Slack、飞书只预留 `SourceAdapter` 文档适配接口，本次不接入。

BFF 部署须使用 `CONNECTORS_MULTIUSER=1`，并在 `CONNECTORS_PROVIDERS` 中启用 `gmail`；上游网关须提供 Gmail 服务和对应动作。Lynclaw 端须包含上述 Wiki 任务扩展，旧服务版本会拒绝新任务；本次只修改本地代码，未自动部署。当前仅通过模拟网关和模型调用验证授权、分页、只读动作、模型复用和账号隔离，尚未使用真实 Gmail 账号或真实付费模型验证。本次未部署 BFF 或发布桌面应用。
