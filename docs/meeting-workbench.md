# P0 / P1 本地会议工作台

> 2026-10-19：本地知识库 / Wiki 的当前入口、模型接口、同步门槛与发布流程以 [local-wiki.md](local-wiki.md) 为准。下文保留此前会议工作台的实现与验证记录；其中自动生成记忆、独立设置卡片和复用聊天模型的描述已被新实现替代。

本期入口是 **设置 → 笔记同步 → 会议记忆**。主开关会沿用现有知识库目录；未配置时启用既有的 `Documents/Lynse知识库` 默认目录。AI 处理另有开关。首次会议全量同步未完成、有下载失败或手改冲突时，不开放会前回顾。会议原文仍可阅读。

## 数据与任务

- Rust 使用经过 token 验证的 `/api/business/customer/current` 身份，按 `SHA256(业务服务地址 + 账号 ID)` 隔离任务与资料。token 只在内存，离线身份缓存以服务地址和 token 哈希为键；明确的身份拒绝不会回退缓存。
- `/api/business/file/page` 从第一页开始完整分页，不带年份、搜索或当前页面筛选。检查 total/pages、重复页与提前空页，避免将部分数据当作全量成功。文件夹列表和全部待办成功后才提交云端会议详情。
- 每场会议在知识库 `Meetings/<scope>/` 中保存一个 Markdown 文档和一个结构化来源伴随文件。包含完整转写、说话人和毫秒时间轴、大纲、全部已有纪要、待办、标记与原始 ID。没有另建应用数据正文库；音频沿用原文件或联网按需播放。
- `.search-index.json` 只保存检索词和来源版本，损坏或缺失可重建。检索结果返回前仍核对原文哈希与当前授权；本地手改不会静默进入 AI。
- 应用数据目录 `workbench/<scope>/state.json` 保存开关、清单、别名映射、进度及失败版本。后台每两分钟补齐变更，并在登录、恢复运行及网络恢复时唤醒。手动“同步全部会议”重试失败版本；恢复唤醒不清除已耗尽的重试状态。
- 每份详情及每段 AI 请求首次失败后最多自动重试两次。失败版本等待用户重试，来源、模型选择或提示词版本变化后重新计算。
- 本地录音上传云端后，旧 ID 映射到云端 ID；保留已有纪要版本和固定条目，不再次索引本地副本。

## 原文、整理与记忆

旧版摘要导出也检测手改；首轮接入时将手改作为冲突保留。手改冲突保留 Markdown，并写入 `.incoming.md` 和 `.source.incoming.json`。用户可保留本地或采用云端；保留本地时留备份并记住已处理的云端版本，下一次同步不会覆盖同一份手改。

录音仍使用现有会话、托盘及悬浮窗。手动录音不再因 60 秒静默停止；自动检测录音保留原策略。重点、决定、待办标记由 Rust 原子写入 `markers.json`，包含媒体时间及来源引用。Mac WAV 写入每两秒更新文件头并刷写。保存后，后台在已安装默认本地模型时进行转写，否则保存为待转写。

会议正文先入知识库，再按独立授权生成纪要、建议待办及带证据的记忆。重新生成追加版本；用户编辑的版本保留。待办只在确认后写入现有列表，ID 由账号、来源和建议 ID 确定，重复确认可恢复且不重复创建。待办的来源引用可打开原文，有可靠时间戳时定位音频。

记忆区分事实、提议、决定和待确认，保留引用和来源版本。不同会议的矛盾并列保留；项目回顾要求模型将未解决的矛盾作为问题。条目支持纠正、固定及排除。已变更来源上的固定/纠正条目显示为待确认，不继续作为有效证据。

衍生条目、纪要版本、`MEMORY.md` 和每日快照位于知识库 `Memory/<scope>/`。排除或删除来源时同步清理历史快照中的相关衍生内容。关闭功能或知识库开关停止处理与引用，原文保留在所选知识库目录；不会迁往应用数据目录；清空只清理衍生资料和可重建索引。账号或授权变化取消后台任务，并拒绝过期结果。

## 助手和服务端契约

桌面助手按问题取最多 3 份原文片段与 2 份有效记忆，每条最多 1,800 字符，通过仅当轮有效的 `desktopContext` 提供。使用现有模型设置；本地记忆不自动写云端长期记忆。

新增只读 MCP 工具：`search_local_memory`、`get_local_memory`、`get_local_memory_source`。工具实现会检查功能、AI 授权、首次同步、单条排除及调用前后的账号/资料版本。

AI 服务修改位于相邻的 `lynclaw` 仓库：

- `runtime/desktop_synthesis.py`：`POST /api/desktop/synthesize`。支持 `meeting_summary`、`memory_extract`、`project_review`，身份仅从现有 token 验证派生；不启动聊天代理或工具，不写会话/云端长期记忆。
- `runtime/desktop_context.py`：当轮上下文，执行结束及异常时清理。`api_server.py` 校验并脱敏，代理适配器仅在当前输入中加入引用。
- `runtime/client.py`：合成调用关闭追踪，日志不含正文、返回正文或凭据。

不同 AI 服务地址先使用现有 `/api/session/backend` 绑定业务来源。自托管若将 AI 和业务网关放在同一地址，需要将 `/api/business/ai/desktop/synthesize` 转发至新端点。生产 AI 服务需发布本轮服务端变更后才能使用合成；未发布时下载和本地阅读仍可独立使用。

## 发布前原生验收

本轮没有对真实账号执行全量下载，没有修改用户实际知识库。以下验收仍待真实原生环境及服务端发布后执行，不能用 renderer bridge 替身或单测代替：

1. 真实跨年份账号逐项核对完整转写、全部纪要和待办；重启/断网续传、磁盘不足和不可写目录。
2. 连续录音 4 小时，覆盖静默、暂停、窗口切换和强杀恢复；测量恢复缺口与来源回跳误差均不超过 5 秒。
3. 实际音频按需播放、上传云端后的来源映射、跨账号切换，以及生产 AI 的结构化输出联测。
