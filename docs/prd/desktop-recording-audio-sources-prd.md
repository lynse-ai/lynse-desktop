## 1. 背景与问题

用户反馈：电脑没有麦克风时，应用仍然录到了电脑播放的声音，但界面没有相应波形。用户无法确认录音是否正常，也不知道当前究竟录制了哪些声音。

双路录音还存在控制上的需求：用户可能只想录电脑声音，或只想录麦克风。应用需要在自动回声消除之外，提供明确、可随时操作的音源开关。

本需求解决三个相互关联的问题：

1. **知道正在录什么**：明确展示电脑声音、麦克风，或两路同时录制。
2. **决定录什么**：录音前及录音中，都能独立控制两路音源。
3. **确认确实录到了**：实时波形与实际保存的声音一致，录音完成后的回放也有对应波形。

### 1.1 当前实现核查

| 现状 | 对需求的影响 |
|---|---|
| 会话已包含 `micLevel` 与 `systemLevel` 两路音量 | 实时来源反馈已有部分基础 |
| 主录音页的波形及字幕页底部录音条只接收麦克风音量 | 仅电脑声音有输入时，这些位置不能正确反映录音活动；这是已确认的代码问题 |
| 悬浮窗已有组合两路音量的显示逻辑 | 不同录音界面的反馈口径不一致 |
| 实时翻译页面已有“双路 / 麦克风 / 系统音频”选择，但录制中禁用 | 已有录前模式配置，仍缺少录制中独立开关 |
| 回放波形独立解码音频，仅提取第一个声道；对超过 80 MiB 或 20 分钟的音频跳过生成 | 回放没有波形可能涉及解码、文件大小、时长或声道；不能直接归因为没有麦克风 |
| 部分启动入口会先请求麦克风权限，再判断所选音源 | 仅录电脑声音的流程需要统一按所选来源检查权限 |

**事实边界**：用户报告的“无麦克风仍录到电脑声音”是需求场景，不视为所有平台均已实现可靠自动降级。开发时须分别核查设备缺失、权限未授予和采集失败的真实行为。

## 2. 产品目标与范围

### 2.1 目标

- 用户在主录音页可直接看到当前实际录音来源，无需进入设置。
- 支持仅电脑声音、仅麦克风、双路录音三种模式，并可在同一录音内切换。
- 无麦克风但电脑声音可录时，默认录音流程可继续，且来源和波形准确。
- 用户关闭的音源不会继续进入录音文件、原始轨、转写或上传链路。
- 设备异常、静音、用户主动关闭三种情况有不同反馈。

### 2.2 本期范围

| P0 必须交付 | 后续范围 |
|---|---|
| 主录音页来源摘要、两路开关及独立音量反馈 | 按应用选择电脑声音，如只录某个会议软件 |
| 录前检查、无设备降级、权限提示 | 完整多轨编辑、混音台、独立增益调节 |
| 录音中切换、暂停恢复、异常状态同步 | 新增高级回声消除参数面板 |
| 主录音页、字幕录音条、悬浮窗显示一致 | Web 端录音能力改造 |
| 自动回声消除与开关联动 | 对全部历史录音批量补建波形和来源信息 |
| 新录音的实时与回放波形、来源记录 | 来源切换历史的可视化时间轴 |
| 所有桌面启动入口采用相同规则 | 全量历史来源推断 |

已有设备选择能力继续使用，本期不要求增加完整设备管理页面。来源状态的可见性与控制能力须覆盖 macOS 和 Windows；平台差异不得用错误的“正在录制”状态掩盖。

## 3. 用户场景

| 场景 | 用户意图 | 预期行为 |
|---|---|---|
| 无麦克风的电脑播放视频 | 录下视频声音 | 显示“仅录制电脑声音”，电脑声音驱动波形，提示未检测到麦克风 |
| 线上会议，用户参与发言 | 同时录下对方与自己 | 两路开启，显示“双路录音”，自动进行回声处理 |
| 观看课程，周围有人说话 | 只录课程 | 关闭麦克风，环境声音不进入麦克风轨及后续处理 |
| 线下会议，电脑可能弹通知 | 只录现场 | 关闭电脑声音通路，仅采集麦克风 |
| 会议中临时不想录现场 | 保留对方，停止本地收音 | 直接关闭麦克风，电脑声音持续录制，不创建新录音 |
| 录音中麦克风断开 | 保住仍可录制的内容 | 若原本双录，继续电脑声音并明确提示；若只录麦克风，则自动暂停 |

“关闭电脑声音”表示关闭系统音频的直接采集。若扬声器外放且麦克风开启，麦克风仍可能拾取外放声音；相关说明见文案规范，不能承诺声学隔离。

## 4. 核心产品规则

### 4.1 来源命名与模式

两路来源分别用**电脑图标**和**麦克风图标**表示，图标按钮同时承担状态展示和点击开关功能。开启时显示正常图标；关闭时在图标中间叠加一条从左下到右上的斜线（`/`）。

来源名称统一为“电脑声音”和“麦克风”，用于悬停说明、异常提示和无障碍标签。“系统音频”可保留在技术文档中，用户侧不使用“电脑本地音频”，以免被理解为本地音频文件。下表的来源摘要文案用于悬停说明和读屏；正常状态以图标组合表达，无需常驻重复文字。

| 麦克风实际开启 | 电脑声音实际开启 | 来源摘要 |
|---|---|---|
| 是 | 是 | 正在录制：电脑声音 + 麦克风 |
| 否 | 是 | 正在录制：仅电脑声音 |
| 是 | 否 | 正在录制：仅麦克风 |
| 否 | 否 | 不得显示正在录音；显示未开始、已暂停或异常状态 |

开启与有声音是两回事：音源已正常工作但暂时无输入，仍属于“开启 · 暂无声音”，不能因此判断设备缺失或自动关闭该路。

### 4.2 默认选择与偏好

1. 未设置偏好的用户，默认选择双路录音；开始前展示两路选择及可用情况。
2. 录音前用户手动选择的来源作为下次启动偏好，沿用现有来源设置，避免引入第二份冲突配置。
3. 录音中的开关只影响本次录音，不自动改写下次启动偏好。避免一次临时关闭导致后续会议漏录。
4. 设备或权限异常造成的自动降级，不覆盖用户原有偏好。
5. 页面、快捷录音、托盘、悬浮入口及会议自动录音，统一读取偏好并按相同规则解析实际来源。

### 4.3 可用性与降级

| 用户选择 | 可用情况 | 处理规则 |
|---|---|---|
| 双路 | 两路均可用 | 双路开始 |
| 双路 | 仅电脑声音可用 | 仅录电脑声音，持续显示麦克风不可用原因 |
| 双路 | 仅麦克风可用 | 仅录麦克风，持续显示电脑声音不可用原因 |
| 仅电脑声音 | 电脑声音可用 | 开始，不申请麦克风权限 |
| 仅麦克风 | 麦克风可用 | 开始，不申请电脑声音权限 |
| 仅某一路 | 所选来源不可用，另一路可用 | 不自动改录另一路；给出开启另一路或修复当前来源的操作 |
| 任意模式 | 所选来源均不可用 | 阻止开始并展示原因；不得空录或显示正常录制 |

双路降级只允许保留原本已选择的来源，不得扩大采集范围。权限处于首次待授权状态时，按用户选择触发必要授权；用户拒绝或授权后仍不可用时，再执行上表规则。自动录音不弹出系统授权流程，缺权限时按同一规则降级或跳过，并给出可见结果。

区分“未检测到设备”“未授权”“设备被占用或启动失败”“暂不支持”和“正在检测”。不能以音量为零判定无设备，也不能把设备枚举不支持返回的空列表当成无麦克风。

## 5. 界面与交互

### 5.1 主录音页

在波形、计时和主要操作附近常驻两个音源图标按钮，无需悬停或打开设置即可识别来源及开关状态。图标本身可点击，不再为每一路重复放置文字标签和独立开关。每个图标附近保留紧凑音量反馈；具体视觉沿用现有组件和设计令牌。

以下“电脑图标 / 麦克风图标”为线性图标的示意标注，不作为界面文字：

```text
录音中                                     00:12:36

[电脑图标]  ▂▄▆▃▅     [麦克风图标]  ▂▃▅▂▁

自动回声消除已启用
────────────────── 实时总波形 ──────────────────
                   [暂停] [结束录音]
```

无麦克风时：

```text
录音中                                     00:12:36

[电脑图标]  ▂▄▆▃▅     [麦克风图标 + 中间斜线 + 异常标记]

未检测到麦克风，当前仅录制电脑声音。
────────────────── 电脑声音波形 ────────────────
```

**图标交互规范**：

- 开启：正常电脑 / 麦克风图标；关闭：同一图标中间加斜线，图标轮廓、位置与尺寸保持一致。斜线应穿过图标中心，清晰可辨，不能仅靠降低透明度表示关闭。
- 点击开启的图标请求关闭，点击带斜线的图标请求开启；斜线表示当前状态，不能把“关闭动作”的图案误作当前开启状态。
- 电脑声音优先复用现有电脑 / 显示器线性图标，麦克风复用现有麦克风图标；关闭态使用对应带斜线版本，没有现成图标时使用一致的斜线叠加样式。
- 悬停及键盘聚焦时显示“电脑声音：已开启，点击关闭”或“麦克风：已关闭，点击开启”；最后一路不能关闭时，显示对应暂停引导。
- 无设备、未授权或采集异常时，使用带斜线图标并附加异常标记，常驻原因提示；不能仅用斜线把这些情况混同为用户主动关闭。
- 暂时静音或被回声处理抑制时，只让音量反馈回到基线，不加斜线。暂停期间图标保留恢复后采用的来源选择，由明确的“录音已暂停”状态说明当前未收音。

录音前图标表达将采用的来源选择；检测中显示“正在检查录音来源”。录音开始后以采集引擎确认的实际状态更新图标和“录音中”状态，不能仅根据设置值显示成功。

### 5.2 单路状态

| 状态 | 展示 | 可用操作 |
|---|---|---|
| 已开启且有输入 | 正常图标，音量条变化；悬停显示开启 · 正在收音 | 点击关闭 |
| 已开启但静音 | 正常图标，静音基线；悬停显示开启 · 暂无声音 | 点击关闭、查看设备说明 |
| 用户关闭 | 图标中间加斜线，音量条归零 | 点击开启 |
| 设备缺失 | 带斜线图标 + 异常标记；常驻未检测到麦克风 / 未检测到输出设备 | 查看设备说明；设备恢复后可开启 |
| 未授权 | 带斜线图标 + 异常标记；常驻需要授权提示 | 点击授权或打开系统设置 |
| 采集失败 | 带斜线图标 + 异常标记；常驻可理解的异常原因 | 点击重试 |
| 平台不支持 | 带斜线图标置为不可用；显示当前环境不支持录制此来源 | 查看说明 |
| 切换中 | 图标附近显示进行中反馈，保留原实际开关状态；悬停显示正在开启 / 正在关闭 | 暂时禁止该路重复提交 |

异常原因持续显示到问题恢复或用户主动取消选择；Toast 只用于辅助反馈。状态不能只靠颜色区分；图标按钮需支持键盘、焦点及读屏，通过可访问名称和开关状态表达来源、是否开启及可执行操作，音量变化无需逐帧播报。

### 5.3 录音中独立开关

- 双路录音时关闭麦克风，立即切换为仅电脑声音；反向同理。
- 单路录音时可开启另一路，成功后切换为双路；重新开启需检查设备及相应权限。
- 正常切换不结束当前录音，不重置计时、标记或已产生的转写，不生成第二条录音记录。
- 采集引擎确认后才显示切换成功，并同步主窗口、字幕页录音条和悬浮窗。
- 本期仅提供三种录音模式：不允许主动关闭最后一路，给出“至少保留一个录音来源；如需临时停止收音，请暂停录音”。暂停入口保持可见。
- 暂停时冻结波形和计时，保留来源选择；可调整选择，恢复前重新校验可用性。暂停中不得因调整开关而提前收音。
- 开启失败时，保留原有正常来源并提示失败。关闭失败或超时、无法确认该路已停止时，自动暂停整段录音并提示“未能关闭麦克风，录音已暂停”，不得显示该路已关闭却继续采集。

**关闭的生效范围**：从引擎确认的生效时间起，该路停止采集，不再写入原始轨、处理轨、混音，不再向实时识别、翻译或云端发送新音频。已进入队列的生效时间之后的音频帧必须丢弃，不能通过缓存继续流出。

关闭前已录制的内容正常保留；关闭前已发送的音频可能延迟返回转写，须按原始时间归属，不能误算为关闭后仍在收音。之后重新开启只从新生效时间开始，不能恢复关闭期间的内容。离线转写、重处理及后续上传也必须尊重关闭区间。

### 5.4 悬浮窗与其他入口

- 主录音页与字幕页共用来源区，切换页面不丢失选择和实际状态。
- 悬浮窗收起态使用电脑和麦克风图标组合表示当前来源，关闭一路同样加斜线；展开后提供与主录音页一致的可点击图标和独立音量反馈。可访问名称需包含完整来源及状态。
- 托盘、快捷入口和自动录音启动后，悬浮窗可直接看见实际来源；发生降级时展示原因，不能只在未打开的主窗口提示。
- 所有界面共用同一会话实际状态。任一位置操作后，其余位置随引擎状态同步更新。

## 6. 波形规则

### 6.1 实时录音

1. 仅录电脑声音：由电脑声音的实际录制信号驱动，麦克风缺失或静音不能影响波形。
2. 仅录麦克风：由麦克风实际录制信号驱动，电脑声音不得影响总波形。
3. 双路：总波形反映进入最终录音的两路混音；每一路另有独立音量反馈，帮助定位来源。
4. 总波形的测量位置须在来源开关和适用的回声处理之后。关闭来源的残留音量、未写入录音的原始回声，不应驱动总波形。
5. 全部有效来源暂时静音时，显示低幅静音基线和“暂无声音”，不生成假起伏，不判断为录制失败。
6. 暂停时冻结；恢复或切换时保持已有时间轴和波形，不清空历史。来源中断期间按真实录音时间保留缺口，不把前后音频压缩拼接。

实时总波形用于反馈录音活动，不要求显示采样级音频细节，但能量必须来自实际保留的音频。已有的双路音量可以作为输入基础，需核查测量位置，不能只更换界面文案。

### 6.2 录音完成后的回放

- 新录音的回放波形从最终播放音频生成，并关联对应音频版本，覆盖单路、双路和途中切换来源的情况。
- 多声道音频需要综合各声道信号，不能只因第一个声道静音就呈现整段无声；只有右声道有声音也应可见。
- 新录音应生成并缓存轻量峰值数据；长会议不能仅因为超过现有浏览器解码阈值而永久没有波形，不能以整段加载高内存作为解决方案。
- 停录后峰值尚未就绪时显示“波形生成中”，仍可播放和拖动；失败时显示“波形暂不可用”及重试操作，保留进度条。
- 切换到另一段音频、另一音轨或重新处理后的文件时，立即清除旧波形，再读取对应峰值，不得沿用上一次结果。
- 已有分轨试听入口可继续使用；选择单路试听时，波形对应所试听音轨。“全部”对应最终混音。本期不新增完整多轨编辑器。
- 历史录音按现有兼容策略播放，无法生成波形时明确降级；来源未知时显示“来源信息不可用”，不得根据当前电脑设备推断历史来源。

## 7. 自动回声消除

- 两路实际开启且处理能力可用时，默认自动启用回声消除，减少电脑外放被麦克风重复录入。
- 只有一路开启时，不需要进行两路之间的回声消除；关闭电脑声音后，不得为维持回声参考而继续隐式采集电脑声音。
- 自动回声处理不能改变用户的音源选择，也不能把被算法抑制的麦克风显示为“用户关闭”。双录时麦克风暂时没有有效语音，仍显示开启。
- 恢复双录后，自动恢复适用的回声处理；重新建立参考期间不能吞掉用户的有效讲话。
- 回声处理异常时，优先保留有效语音，显示“回声消除暂不可用，可能录入重复声音”，记录异常区间；用户可以直接关闭任一路。
- 本期不新增手动调节回声算法的专业设置，保留现有处理能力并补齐与来源切换的联动。

## 8. 设备变化与异常

| 异常 | 录音行为与界面反馈 |
|---|---|
| 双录中麦克风断开 | 保留电脑声音，来源摘要改为仅电脑声音；提示“麦克风已断开，当前仅录制电脑声音” |
| 双录中电脑声音采集失败 | 保留麦克风，来源摘要改为仅麦克风；明确提示电脑声音未录入 |
| 单路录音的唯一来源失效 | 自动暂停，提示原因及修复操作；保留已录内容，不切换到未选来源 |
| 两路均失效 | 自动暂停；不得仅让计时继续并显示正常录制 |
| 不可用来源重新连接 | 更新为可开启，由用户手动恢复；本次录音不悄悄增加来源 |
| 用户已关闭的来源恢复 | 继续关闭，不能被设备恢复、权限恢复或自动重连开启 |
| 正常跟随系统默认设备切换 | 沿用已有“跟随系统默认”选择；该类来源原本已开启时可继续跟随，更新设备说明；失败则执行失效规则 |
| 关闭后仍收到旧音量事件 | 按会话及切换版本过滤，关闭来源音量不反弹 |
| 只有静音而无采集异常 | 继续录音，不按音量为零降级；自动录音的既有静音结束策略只参考有效来源 |

设备状态未知时显示检测中或检测失败，不能报成“没有设备”。若原生平台无法确认来源已启动，该路不能计入“正在录制”的来源集合。

## 10. 数据与实现约束

本节明确研发必须满足的行为合同，不限定具体 IPC 或存储实现。

- **区分偏好与事实**：保存用户选择、来源可用性、引擎实际开启来源及失败原因；不能用一个 `both` 配置值代替所有状态。
- **原生状态为准**：启动与切换返回实际生效来源、录音时间轴上的生效时间和递增切换版本；多窗口共享同一状态，重开页面可恢复。
- **录音来源记录**：为新录音保存来源生效区间、变化原因和回声处理异常区间。暂停沿用既有时间语义；所有区间、标记、转写和峰值使用相同录音时间坐标。
- **录后来源摘要**：详情可显示“仅电脑声音”“仅麦克风”或“包含电脑声音和麦克风”。两种来源曾先后使用时，不把整段标成“全程双路”。本期不要求展示完整切换时间轴。
- **关闭区间不可恢复内容**：该路可保留结构性的静音占位或区间标记以维持对齐，但不得保留关闭期间真实音频；后处理不能重新混入关闭内容。
- **波形元数据**：保存峰值、时长、时间刻度及音频版本标识；同步后再打开仍可获得对应波形。若同步链路需要扩展，属于本需求依赖，不能悄悄丢弃。
- **统一来源解析**：录音来源控制与转写服务商配置解耦；所有入口共用相同规则。共享 UI 遵循 `views → core + ui` 边界，平台采集能力通过既有桥接层暴露。
- **兼容旧录音**：新增字段允许缺省；缺来源信息不影响播放，缺峰值可尝试补建或明确显示降级状态。

## 11. 验收标准

以下为拟定的产品验收目标，不是当前已达到的性能结论。

| 编号 | 场景 / 操作 | 必须满足的结果 |
|---|---|---|
| AC-01 | 无可用麦克风，电脑播放音频，以默认双路启动 | 实际仅录电脑声音；常驻无麦克风提示；实时波形变化；停录后可听到声音且有回放波形 |
| AC-02 | 有麦克风，仅选电脑声音，麦克风尚未授权 | 不弹麦克风授权；不采集麦克风；录制成功 |
| AC-03 | 仅选麦克风，电脑声音未授权 | 不索取电脑声音权限，麦克风录音可开始；电脑直采不进入文件 |
| AC-04 | 两路开启，分别只给电脑声音或麦克风输入 | 各自音量条正确变化，总波形均可响应，来源摘要始终为双路 |
| AC-05 | 双录中关闭麦克风，并在关闭后对其讲话 | 单条录音不中断；生效后麦克风真实音频不进入任何保存轨、混音、转写或上传；电脑声音保留 |
| AC-06 | 双录中关闭电脑声音，随后播放测试音频 | 系统直采停止；使用耳机或隔离输入排除声学串音后，保存及转写中无该路新增内容 |
| AC-07 | 由单录重新开启另一路 | 同一录音内恢复双路；关闭期间内容不能在原始轨、重处理或上传后重新出现 |
| AC-08 | 尝试关闭最后一路 | 不进入零来源录音；明确引导暂停；暂停与恢复正常 |
| AC-09 | 暂停、调整来源、恢复 | 暂停期间无新采集；恢复采用新选择；计时、标记及已有内容符合原有暂停语义 |
| AC-10 | 麦克风拔出后重新插入 | 按原选择继续另一已选来源或暂停；插入不会自动增加本次采集来源；手动开启后才开始录入 |
| AC-11 | 明确选择仅麦克风，但麦克风不可用 | 不自动改录电脑声音；展示修复或用户主动切换操作 |
| AC-12 | 所有已选来源失效，或关闭操作失败 | 自动暂停并给出原因；不能假报关闭成功或继续显示正常录音 |
| AC-13 | 两路开启但都暂时静音 | 显示静音基线，不伪造活动波形，不因无输入报无设备 |
| AC-14 | 主窗口、字幕页、悬浮窗交替操作；快速重复切换 | 状态最终一致；旧版本事件不覆盖新状态；关闭来源不因旧事件重新开启 |
| AC-15 | 双录外放、同时讲话、切为单录再切回 | 回声处理随实际来源变化；无明显新增重复录音或有效讲话丢失；既有回声测试不回退 |
| AC-16 | 新录音超过 20 分钟或 80 MiB，包含 2 小时会议 | 使用峰值缓存或等效低内存方案显示回放波形，不能永久退化成无提示的普通进度条 |
| AC-17 | 回放右声道单独有声、切换音轨、切换文件、重处理 | 各自正确显示波形，无旧波形残留；波形与当前播放音频对应 |
| AC-18 | 峰值生成失败或缺失；打开历史录音 | 播放与拖动仍可用；有明确波形状态及适当重试；历史来源未知时不编造 |
| AC-19 | 页面、托盘、快捷入口、悬浮入口、自动录音启动 | 偏好和降级规则相同；实际来源与异常均可见；自动入口不绕过用户关闭选择 |
| AC-20 | 重开应用、录后重开详情、同步后重新打开 | 启动偏好正确保留；本次临时开关不污染下次偏好；新录音来源记录及波形可恢复 |
| AC-21 | 检查两路图标的开启、关闭、静音、异常及切换中状态 | 开启为正常图标，关闭在图标中心加斜线；静音不加斜线；不可用附异常说明；切换确认前不假报成功；主录音页、字幕录音条和悬浮窗表达一致，键盘及读屏可操作 |

### 11.1 响应与稳定性目标

- 点击开关后 100 ms 内给出进行中反馈；正常设备条件下 1 s 内完成切换并显示引擎确认结果。超时按失败规则处理，不无限等待。
- 有效声音进入采集链路后，实时音量和总波形在 500 ms 内有对应反馈。
- 启停、来源切换及设备失效在引擎发出状态后 1 s 内同步到所有已打开的录音界面。
- 新录音停录后，波形缓存应在 5 s 内可用；峰值生成不得阻塞音频保存或播放。2 小时录音也需通过此项，不能依赖停录后全量重新解码。
- 来源切换不丢失持续开启的另一来源；需要重建采集导致间隙时，须记录并在测试中量化，不得无提示截断语句。
- 在 macOS / Windows 分别验证无输入设备、内置设备、USB 麦克风、耳机，以及权限拒绝、设备热插拔、长录音和自动录音。
