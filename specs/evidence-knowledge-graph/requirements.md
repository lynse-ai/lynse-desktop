# 有证据的会议知识图谱：一期需求

状态：用户已授权直接实施；旧图谱不保留或兼容。实现与验证见 design.md 和 tasks.md。
日期：2026-10-21。

## 目标与边界

图谱的主要用途是回答与人、事、责任和变化有关的问题，并能回到授权的原话或录音片段。Topic（话题）作为导航与分组维度；项目作为 Entity（实体）的一种类型。增加节点种类本身不视为完成。

一期以三个用户问题验收：

1. 谁负责什么？按人员或项目查看责任、参与及其生效时间和来源。
2. 哪些任务尚未完成？区分已确认待办、讨论中的任务建议、状态未知和有完成依据的任务。
3. 某项目有哪些决策和风险？查看带时间的决策、问题、风险及后续变更，每条都可追溯。

一期支持有授权的用户选择来源与后续新增/变更来源的受控抽取，不默认对全部历史录音重新分析。直接替换既有图谱，不读取或迁移旧图谱缓存。独立 Wiki、原始来源与其审阅历史保留；没有依据的说话人、时间点与状态保持未知。

## 最小信息要求

此表定义产品必须保留的信息，不预先决定物理存储、API 字段命名或图数据库技术。

| 信息对象 | 必须表达的内容 |
| --- | --- |
| Entity 实体 | 类型、显示名、原文提及、别名候选、身份确认状态、作用域；同名不等于同一实体 |
| Relation 关系断言 | 主体、带类型和方向的关系、客体或属性值、适用时间、肯定/否定、提议/转述/已确认等语气、证据、确认状态 |
| Event 事件 | 任务、决策、承诺、问题、风险、变更、里程碑等类型；参与者及其角色、涉及项目/对象、状态、发生时间和期限 |
| Topic 话题 | 导航标签与可选层级；关联实体和事件；话题共现不自动构成责任、依赖或因果关系 |
| Source / Evidence 来源与片段 | 来源录音/文档 ID、内容版本、片段 ID 或文本范围、原话、录音偏移、说话人标识及身份确认情况 |
| Time 时间 | 会议发生时间、断言适用时间、事件发生时间、截止时间、记录/抽取时间分别保存；保留相对时间原文和归一化依据 |
| Confidence / Review 置信与审阅 | 抽取置信度及其来源、文本/时间对齐校验结果、身份确定性、人工确认状态；未知可为空，模型自评分不当作已校准概率 |

实体分类应能容纳人员、组织、部门、地点、产品、项目、文档、术语、系统、客户和供应商。一期优先抽取三类查询需要的人员、组织/部门、项目、产品、文档。其他类型允许保留为候选，不宣称已完成所有类型的可靠自动识别。

情绪/态度/需求可作为后续有主体和对象的断言；一期仅将有明确措辞的风险或问题纳入第三类查询，不根据音色推断情绪、人格或隐含意图。

## 用户故事与验收条件

### R1：按人员和项目找责任

作为用户，我希望选中一个人或项目就能知道谁负责什么、谁参与什么、依据是什么。

- 当用户查询某人或项目的责任时，系统应返回有明确责任措辞或有效人工确认的关系，并同时展示来源、适用时间与确认状态。
- 当录音仅提到某个人或项目名称时，系统不得据此建立负责关系。
- 当原文表达未来安排、条件或他人转述时，系统应保留该限定，不将其转成已接受的本人承诺。
- 当来源明确表达负责人变更时，系统应保留前后关系及各自依据，展示变化时间，不以覆盖旧记录的方式丢失历史。

### R2：找未完成任务

作为用户，我希望找到明确待办，并能分清讨论中的建议和已经确认的任务。

- 当录音出现任务安排时，系统应保留动作、负责人候选、接收人、交付物、关联项目、期限原文、证据及接受状态；未明确的信息应为空或未知。
- 当只有一句未来安排而没有接受依据时，系统应标注为计划/待确认，不自动创建或分配真实待办。
- 当用户确认创建任务时，系统应复用现有待办确认流程并建立稳定关联；重复确认不得创建重复任务。
- 当查询“尚未完成”时，系统应区分有待处理状态依据的任务与完成情况未知的任务；未在后续会议中提及不得视为未完成或已完成。
- 当任务已经与真实待办关联时，系统应注明状态来自待办系统还是录音断言；二者冲突时并列展示，不静默覆盖。

### R3：找项目决策和风险

作为用户，我希望看到某项目决定过什么、有哪些风险，以及后续是否发生改变。

- 当用户打开项目时，系统应提供决策、问题、风险、任务及变更的时间列表，并允许筛选类型。
- 当原文是建议、假设、否定或未达成一致时，系统应保留其语气与分歧，不转成已通过的决策。
- 当不同来源对同一事项有不同说法时，系统应显示各自的时间、说话人和依据；仅凭新旧顺序不得判定较新的陈述已推翻旧决策。
- 当记录有明确撤销、取代或解决依据时，系统应显示相应变更及证据链。

### R4：每个断言回到证据

作为用户，我希望每个责任、任务、决策和风险都能回到原话。

- 当系统接收抽取结果时，应验证引用在相应版本的授权文本中真实存在，且所用片段属于该来源；无有效证据的断言不得进入已确认事实查询。
- 当来源有可靠片段时间时，打开证据应定位到对应原文，并提供播放相应录音位置的入口。
- 当时间点不存在或原话匹配多个片段时，系统应显示可核实的文本位置或多个匹配，明确标注尚未定位，不取第一个匹配冒充确定时间点。
- 当断言涉及多轮对话或指代时，应保留所依赖的片段序列与各自说话人，不能只引用结论片段而丢弃指代依据。
- 当重试或重新抽取时，系统不得静默覆盖原始录音、转写或用户手工修正。

### R5：身份与指代

- 当说话人只是“说话人 1”或一个声纹标签时，系统不得自动认定其为原文提及的张三，也不得认定为当前登录用户。
- 当原话中有同名人物或名称不明确时，系统应保留独立实体/提及候选，等待明确证据或人工归并；名称相同不能作为跨会议自动合并身份的唯一依据。
- 当“他”“这个方案”等指代无法唯一解析时，应保留原文、候选指向与未知状态，不强制建立唯一关系。
- 当用户纠正身份或归并实体时，相关显示应更新，原始提及与纠正依据应保留，并能撤销错误归并。

### R6：时间与期限

- 当解析“周五”“下个月”等相对时间时，应使用可靠的会议发生时间和时区，保存原表达及解析依据；不得使用上传时间或当前运行时间代替。
- 当缺少日期锚点、时区或表达有歧义时，应保留原文并标注待确认，不生成确定截止日期或据此判为逾期。
- 当展示时间线时，应区分“何时说的”“事情何时生效/发生”“何时抽取/同步”。

### R7：置信度与质量

- 当展示模型抽取结果时，应区分抽取确定性、说话人身份、ASR 质量、证据对齐和人工确认；不得用一个高分替代全部验证。
- 当没有可信置信度来源时，应显示未知，不默认填入 1.0 或“100%”。
- 当阈值用于自动进入事实查询时，应有标注样本和误判评估作为依据；第一期不能仅凭模型自报分数绕过证据与身份检查。
- 当用户纠正或拒绝候选断言时，应保留反馈，不因下次同版本抽取重新显示同一条已拒绝结果。

### R8：权限、脱敏和失效

- 当读取、抽取、查询或播放证据时，系统应使用已有 token 验证身份和账号 scope；实体名称、邮箱、说话人名称不得充当运行时身份或授权依据。
- 当用户选择来源并允许 AI 处理后，系统才可提交允许使用的文本；需要脱敏的字段应在模型输入边界处理，保留必要映射而不改写本地原文。
- 当校验脱敏输出时，应对照模型实际收到的文本验证；回到原文只通过授权的本地证据映射，不将隐藏字段再次发给模型或写入普通日志。
- 当来源删除、撤权、被排除或语义内容变更时，依赖它的断言应从默认事实查询和 AI 上下文中移除或标为失效；历史访问也必须重新检查权限。
- 当仅发生无关来源新增或纯展示元数据变化时，不应使未受影响断言全部失效；真正的片段/身份/权限变化必须使相关证据重新校验。

### R9：导航与展示

- 当用户选择实体、事件或责任关系时，系统应展示它的类型、相关对象、时间、确认状态和证据；图形布局距离不得被解释为业务关系。
- 当通过话题导航时，系统应能进一步进入相关实体、事件与来源；不能只给一组关键词。
- 当用户展开图谱时，应能完成同样的证据阅读和返回路径；保留已实现的一跳/两跳、搜索定位与有限绘制预算。
- 当关系仅表示共同来源时，应明确标记为共同出现，不显示成责任、依赖或因果。

### R10：替换与运行范围

- 按用户最新指示，直接替换旧图谱，不迁移或兼容旧图谱节点、缓存与人工设置。独立的原始录音和 Wiki 发布记录不属于旧图谱数据，不作删除。
- 当重新分析历史来源时，应先显示选定范围与处理进度，支持暂停、重试和按来源版本去重，不默认发起全部历史录音的模型请求。
- 当模型服务不支持所需结构化契约时，应明确报告服务需要升级，不把嵌入描述字符串的临时结果当成完整新 schema 已落地。
- 当后台抽取刷新时，应保留正在阅读的位置和用户修正，不阻塞普通录音与原文阅读。

## 最小验收语料

以下均为合成样例，采用测试录音与片段标识；不是用户真实会议。

| 原话/条件 | 期望结果 |
| --- | --- |
| “张三负责 A 项目，周五前给李四预算表。” | 识别人、项目、文档；责任关系有证据；提交预算表表达为计划事件，角色和期限各自保存；无锚点时保留“周五”待确认；不能推断任务已提交或张三本人已接受 |
| “我建议采用方案 B，还没定。” | 建议，不能作为已通过决策 |
| “会上决定采用方案 B，方案 A 不再推进。” | 带来源的决策，以及明确取代/停止关系；发生时间与抽取时间分开 |
| “李四担心采购预算超支。” | 有归属的风险表述；不能自动生成“已经超支”的事实 |
| “张三已不负责，改由王五负责 A 项目。” | 保留历史负责人和变更依据，当前责任关系按明确时间更新 |
| “上次说的那个预算他还没给。”且无法定位“他” | 保留未解析指代及证据，不自动归到张三 |
| 两场会议各出现名为“张三”的人员 | 无补充身份依据时不自动合并 |
| 一个任务后来没有再被提及 | 保持原状态/状态未知；不能自动完成或判定逾期 |
| 相同引文在两个时间段出现 | 展示多个匹配或待定位，不选择任意一个作为确定依据 |
| 来源被排除、模型请求返回时账号已切换 | 结果不得写入新账号或进入默认查询 |
| 只改了不参与语义输入的展示标签 | 不使无关断言全部重新抽取或失效 |

## 一期暂不包含

- 根据语气、声纹或音色猜测情绪、人格或身份。
- 无依据的跨会议人物归并、自动代词定指和冲突消解。
- 自动替用户承诺、分派任务、改写真实待办或自动发布 Wiki。
- 自动重跑全部历史录音，或先引入新的图数据库与绘图库。
- 将“图谱视图可画出新节点”作为模型服务、证据对齐和事实查询已完成的证明。
