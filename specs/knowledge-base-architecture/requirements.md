# Lynse 知识库重构需求

2026-11-14 · 新版知识库

面向有持续会议和项目资料的用户。用户应当能在资料入库后搜索原文，看到跨会议的项目进展，沿引用回到原句和录音，并决定哪些内容进入助手的长期记忆。知识库应当能积累几年资料，日常更新的工作量主要由本次变更决定。

## R1 资料可用性与引用

- 当已授权的会议纪要、转写或文件提交成功时，知识库应当先提供来源和可用的全文检索，再异步补齐专题、图谱和语义索引。界面应当显示各阶段的状态。
- 当用户打开引用时，知识库应当定位原版本原句。具备经过校验的音频位置时，应当定位相应录音区间。引用人工笔记或纠正时，应当显示人工来源。
- 当内容重新出现或仅发生有效范围内的目录、时间等元数据变化时，知识库应当复用已完成的正文计算和索引内容，并校验当前引用及访问资格。

## R2 专题与图谱

- 当新会议补充一个现有项目时，知识库应当把有原文依据的决定、进展、风险及问题关联到对应小议题，形成可浏览的大专题、时间线和来源列表。会议提议、异议、已否定内容与已确认结论应当保留各自语义。
- 当来源追加、修订或撤销时，知识库应当能按来源替换对应贡献和引用，并更新受影响的正文小节与图谱关系。仍有其他有效依据的陈述应当可以继续使用。判定新证据与旧结论有冲突时，应当给出原句、时间和结论状态。
- 当用户合并专题、排除来源关联或编辑页面时，知识库应当记录人工决定、原 ID 的跳转及版本历史。后续自动更新应当采用这些决定。需要改写人工文字或已确认结论时，应当显示带差异的候选稿。

## R3 统一搜索与助手检索

- 当用户从知识库、桌面助手、Web 或 MCP 查找资料时，可访问的资料应当经过同一套来源与引用资格规则。搜索返回命中的段落及所在专题，回答应当能回溯到实际支撑的原文。
- 当向量服务不可用或 Wiki 尚在生成时，已就绪的原文应当继续通过关键词检索。界面应当显式显示知识范围和服务降级情况。

## R4 设备、授权与记忆

- 在设备私有资料的使用范围内，桌面应当提供本地浏览、全文搜索及编辑。使用账号级资料时，Desktop、Web 和助手只应看到该渠道有权访问的来源与衍生内容。
- 当来源撤销授权、移出 AI 范围、切到加密保护或被遗忘时，知识库应当在下一次检索、模型提交或结果重放前阻断该来源与依赖它的内容，随后清理对应索引、页面贡献和记忆依赖。暂停整理仅停止新的后台整理任务。
- 当系统根据会议提出记忆或待办建议时，应当以候选形式展示。确认记忆、遗忘和创建业务待办使用各自已有的用户操作与授权。

## R5 增量与恢复

- 当相同的输入被重复同步、应用重启或用户切换写作模型时，已完成且仍有效的内容应当产生零次新的生成调用。首次生成、真实内容变化、显式重新生成、已证实失败的重试按当前路由执行。
- 当同一来源连续到达多个修订时，系统应当合并尚未执行的工作，并以最新有效版本提交结果。当模型超时导致结果未知时，应当恢复回执或显示执行结果未知。收到明确限流或提交前失败时，应当退避后重试对应任务。
- 第二台设备可复用同一知识协议下经过当前证据校验的发布结果。并发编辑、撤销和重试通过版本比较及删除记录收敛。首次启用按当前授权范围建立索引和专题。

## R6 采用与验收

- 以当前 Lynse 为基线，用同一套会议资料、问题、权限和更新场景对比最终方案。搜索或问答至少一项变得更好，另一项及引用质量不得下降。新增资料的生成量和耗时应当低于基线，授权隔离与人工决定的回归应当全部通过。
