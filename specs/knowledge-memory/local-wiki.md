# 图谱优先的本地 Wiki

Wiki 用于浏览知识；问答继续由 Lynclaw 承担。记忆文件的编辑与云端缓存行为见 [markdown-memory.md](markdown-memory.md)。本轮只交付代码和本机验证，不部署服务或发布桌面版本。

## 使用体验

- 默认进入项目和话题图谱。只提供缩放、复位；连线表示共同来源，不代表业务关系。
- 整理进度在知识库首页顶部显示，包含当前阶段、已处理数量及当前会议或专题。可确定总量时显示百分比，未知时使用不定进度；完成后收起。设置页只保留范围、配置和维护。
- 右侧未选中时显示最近变化；选中后显示概览、变化、来源及完整专题入口。
- 专题正文包含当前情况、重要变化、未解决问题与来源；返回恢复选择和视角。目录按名称查找并打开同一份正文。
- 人物与事项在正文中按需展开；不增加主页配置。
- 补充与纠正独立保存、标为人工补充，持续参与后续编译，不覆盖原始会议总结。

## 首次开启和范围

首次只选择会议文件夹并开启自动整理。支持多选，默认全部不选；未分类会议单独选择。开启前明确说明选中会议的可用总结、或无总结时的转写，会发送到当前 AI 服务。自动沿用当前模型和本地同步目录，Gmail 必须在设置中另行开启。

`workbench_configure` 增加可选 `automation: { folderIds: string[], includeUnfiled: boolean }`。旧调用可省略；旧账号必须选择范围才进入新自动流程。暂停保留范围和已有页面，再开启时恢复选项。

文件夹范围用于 AI 整理和引用。本地同步仍可保留其他会议供用户阅读。原生端统一限制来源分析、专题归类与编译、图谱细节、向量检索、聊天上下文和 MCP 读取；界面筛选不作为安全边界。

应用内移动会议成功后，`source_folders` 立即更新原生归属并取消旧任务。同步也会更新缓存会议的文件夹归属；选定范围内的已知来源版本变化会自动下载新文本。范围之外的既有文本沿用原有手动刷新方式。暂停期间不提前推进已知文本版本，重新开启后可追上变化。

取消文件夹、会议移出范围或排除单条资料后，旧依据不再进入新模型请求和 Lynclaw 引用。相关专题重算；历史文件继续保留。原生每次发出模型请求前重新检查账号、同步轮次、范围、授权、排除状态和来源版本。

## 自动处理

原生流程：范围筛选 → `wiki_catalog` 发现/归类 → `source_analysis` 分析 → `topic_compile` 编译 → 引用/版本/哈希校验 → 保存有效版本。

优先使用已有云端总结和当前来源版本下的本地总结；分别过滤无效内容。没有可用总结时使用转写。总结引用固定为 `meeting_summary`，不携带虚构的录音时间点。传输前沿用逐字敏感信息遮盖；原文与本地引用保留原始字符，无法唯一还原的引用被拒绝。

归类返回稳定语境 key、已有专题 ID、项目/话题类型、概览和引用。合并到已有专题必须包含该专题来源依据及新来源依据；名称相同不足以确认身份。新自动专题不参与旧的按标题去重。共同会议只生成 `shared_source` 浏览连线。

归类缓存按来源版本、内容、实际来源类型和模型版本保存；分析缓存还包含专题目的与人工纠正。新增会议复用既有来源分析；未变化输入不重新调用模型。正文相同则更新校验依据，不增加页面版本或重复变化记录。一个专题失败不阻断其他专题。

自动发布记录 `review: auto_validated`，人工确认保留 `approved` 及原确认时间，两者不混淆。保留历史及覆盖前快照；失败保留上次正文，提供重试。过期、越界、校验失败或存在更新错误的专题不进入 Lynclaw 上下文。

外部修改的 Markdown 仍为权威本地文本，自动编译不会覆盖。来源发生冲突时保留两份，并停止 AI 使用，等待现有冲突处理流程。无会议依据的人工补充独立显示，不作为会议事实引用。

## 接口与文件

桌面 Wiki 状态增加 `automation`、`topicGraph`、专题 `overview`、带引用的 `changes`、`history`、来源归属和 `inScope`。图谱、目录、正文使用同一份专题数据；聊天上下文继续使用 version 1 格式。

Lynclaw 的既有 synthesis 路由增加 `wiki_catalog`，并为 `topic_compile` 返回概览与带来源的变化。仍使用已验证令牌身份、当前模型和原有证据校验，不执行工具或模型返回的操作。

- `<vault>/Meetings/<scope>/`：原文 Markdown 与结构化来源。
- `<vault>/Memory/<scope>/wiki/topics.json`：稳定专题 ID、归属、人工纠正、发布版本及历史。
- `wiki/automatic-catalog.json`：归类回执、失败记录和稳定身份映射。
- `wiki/<topic-id>/published.*`、`revisions/`、`edits/`：正文、引用、版本快照和人工修改备份。
- `wiki/index.sqlite`：可重建分析/编译缓存和可选向量。
- 原生账号配置：选中文件夹与未分类选项；模型密钥沿用既有安全存储，不进入上述文件。

旧专题的 ID、页面、历史、人工备注、固定和排除设置保留。已发布旧专题通过其来源参与身份匹配；旧草稿不作为新流程的已验证内容。只有从当前有效依据重新编译并校验的新结果才能自动保存。

## 本轮验证（2026-10-23）

- 原生完整回归 340 项通过、4 项忽略；其中两个本机 HTTP 联调用例单独通过，其余两项为已有非本轮测试。
- views 工作台及聊天传输相关测试 96 项通过；桌面 renderer 测试 35 项通过。
- Lynclaw synthesis、Wiki、图谱相关离线测试 35 项通过。
- 桌面浏览/设置回归 16 项通过：首次多选及未分类、失败保留选择、图谱预览、全文返回视角、目录、来源、历史、人工纠正、范围修改、暂停恢复、失败重试、中文、键盘及窄窗口。
- 本机真实 Lynclaw HTTP → Rust 归类/证据校验/保存 → 实际桌面 renderer 阅读联调通过。身份、模型和会议为合成数据；不使用真实用户账号或付费模型。
- 工作区与桌面 TypeScript、相关 ESLint、生产 renderer 构建及差异检查通过。视觉证据与比较记录见项目根目录 `design-qa.md`。

上述验证不等同于已部署的新服务或已发布的桌面安装器。发布前需部署兼容 synthesis 接口并执行正式发布流程，本轮未执行这些操作。
