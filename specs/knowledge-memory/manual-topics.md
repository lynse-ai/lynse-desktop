# 人工专题

专题目录中的“新建专题”保存名称及关注点。人工专题与自动发现的普通专题分别保存；人工专题尚未生成正文时也可浏览，不参与普通专题身份合并。

人工专题仅关联当前范围内已发布的普通专题。明确相关的自动纳入，存疑的待确认；用户可手动纳入、移出和恢复。一个普通专题可加入多个人工专题，人工选择持续保留。聚合专题之间不关联，也不作为新的原始证据或长期记忆来源。

关联模型读取候选专题引用附近的原文，目录概览只作为辅助上下文。原始转写与会议总结按引用类型分别读取。引用、来源版本、授权和脱敏处理沿用现有知识库流程。

时间线默认最新在前。完整日历日期须由原文引文支持；缺失时使用来源创建日期并标注“记录日期”，不将其称为会议时间。日期未知的条目最后显示；重复事项合并引用，计划和分歧保留原有性质。

## 接口与状态

- `wiki({action:"topic",mode:"collection",title,purpose,id?})` 创建或编辑人工专题，响应 `createdTopicId` 用于定位。
- `wiki({action:"topic_link",id,targetId,state:"included"|"excluded"})` 保存人工关联选择；仅接受普通已发布专题。
- `Topic.collection` 保存关联、证据、事件、处理状态和数量；旧专题该字段为空。
- Lynclaw `/api/desktop/synthesize` 的新任务 `wiki_topic_match` 返回 `relation`、`reason`、`citations`、`events`。事件包含可选 `date`、`dateQuote` 和原始引用。业务代理仍使用现有转发路径。

关联和事件按专题、来源片段及输入版本缓存，概览复用现有编译缓存。新增内容只处理发生变化的关联；重试保留成功回执，人工选择只使对应关联失效。处理中断后继续使用缓存，源版本和授权在发布前再次校验。

## 兼容与交付

先部署支持 `wiki_topic_match` 的 Lynclaw 服务，再发布客户端。旧服务返回 Unknown synthesis task 时，该人工专题显示服务升级原因并停止当前尝试，不循环重做普通专题。源码实现不自动部署或发布服务。

验证覆盖 Rust 专题缓存与引用校验、Runtime 结构化输出校验、前端时间线排序与去重，以及桌面的创建、空目录、AI 关闭、关联确认与恢复、中文进度和服务版本错误。
