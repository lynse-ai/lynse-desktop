# 知识库与共用记忆系统实施计划 v0.4

2026-10-24 实施状态。已合并用户后续决定：新版记忆全新构建，不导入旧版记忆；本文件把实施结果与待验收项分开记录。完整执行证据见 [实施记录](./implementation.md)。

## 产品规则

- 知识库负责浏览，Lynclaw 负责问答与长期记忆；Wiki 自动发布不确认长期记忆。
- 云端记忆记录是唯一权威。Desktop 仅保存缓存、草稿和阅读视图。
- 自动提取仅生成候选。确认须绑定预览和当前依据；显式记住必须来自当前用户请求或 UI 操作。
- 账号共享文件夹范围、未分类选择和排除项；记忆授权单独开启。文件夹不充当项目身份。
- Wiki 暂停、提取暂停、授权撤销、遗忘分别处理。暂停阻断新提交；撤销使依赖内容不可用。
- 本地文本、普通聊天后台提取、邮箱和通知分别授权，默认关闭。音频独立；不传 Desktop 模型密钥。
- v1 面向工作场景。未知、混合场景须复核；确认不改变提议、否定、转述、推断的性质。
- 遗忘后保留 Wiki 专题及原会议、录音、聊天供人工浏览；相关依据停止进入 AI、自动检索和再次沉淀。不能隔离时整份来源及相关专题停止自动 AI 使用。
- 用户已追加授权 CloudBase 上线与 Desktop 1.2.0 构建。源码、测试、云端迁移、部署和正式发布分别记录。

## 固定契约与处理约束

复用既有记录生命周期。权限和遗忘不依赖 cues、标题或 Markdown；结构化来源、版本、授权、证据与陈述性质随纠正保留。人工纠正有独立人工证据，旧会议引文仅保留访问依赖。

新增契约包括 capabilities、desktop-sources、Wiki events、确认预览、explain、forget-plans、source-eligibility 和 memory-projections。Runtime 使用显式白名单；外部业务网关必须独立验证，不能根据 Memory 单层能力自动认定整链路可用。

操作 ID 不随 24 小时响应窗口失去去重；同 ID 不同载荷返回 409。回执保存引用，重放前查当前权限；失效返回 410，版本变化返回 409。遗忘后不从旧请求重建记录。

上传按解码 UTF-8 计量：256 KiB 分片、16 MiB 快照、未提交 24 小时过期，完整提交前不可检索。保留原文，仅传脱敏副本。文本指纹同时覆盖原始版本，不能用等长遮盖掩盖来源变化。

模型在事务外调用，提交重新核验任务租约、来源和授权。每账号同一时刻最多一个模型任务；当前 worker 进程串行执行，满足最多四个的上限。旧 Context 的两个模型阶段和新提取均逐次计入每天 200 次限额；清理不受限。

当前投影采用保留原陈述的编译器，8 KiB 软预算、12 KiB 硬文本预算；不会覆盖人工笔记或提升候选资格。人物按明确 scope ID 分组，不按同名合并。

## 本次新增核验风险

| 风险 | 当前处理与限制 |
| --- | --- |
| 编辑丢失原授权 | 已改为结构化依赖；纠正有人工证明，并保留原授权和敏感性。旧关联不可靠的记录待复核 |
| 旧幂等回执泄露正文 | 新旧 Markdown、Memory action 回执均按引用核验；新增遗忘后重放回归 |
| 原文及缓存绕过遗忘 | Native、MCP、Runtime 来源读取及旧工具结果加入资格检查。资格版本变化时保守清除自动会话视图，原聊天保留 |
| 大级联及恢复 | 已测 602 条遗忘清理与实际 pg_dump/restore。恢复过程先持久关闭读取门槛；全类型验收前不能开放 |
| 正文不变、依据变化 | 事件和上传身份覆盖原始版本、有效输入和处理版本；增加等长脱敏来源变化回归 |
| 旧新管线双写 | 已迁移账号停止旧候选写入；旧聊天自动管线缺少独立能力/授权时不缓冲、不调用模型 |
| 文本乱序/多设备覆盖 | 使用已知服务端版本 CAS；丢失回执可按相同原始指纹恢复，未知设备遇到不同快照拒绝覆盖 |
| 外部接口与能力不一致 | 已查本地项目，未取得业务后端源码。业务待办、Gmail、通知及外部网关保持未完成/不可用 |

## 验收与上线顺序

继续保留权限一致性、来源与确认、遗忘全路径、故障恢复、产品体验和质量评测六组验收。新增问题必须有回归；旧 127 项专项记录不能替代本轮证据。

上线按“创建独立空白 schema 和最低权限账号 → Memory → Runtime/worker 与网关 → Desktop → 小范围账号”执行。运行角色不得超级用户或绕过 RLS。任务与日志不保存凭据、模型密钥和业务正文。

回滚分别关闭上传、提取、投影、通知；授权、失效、遗忘门槛持续生效。不回退到忽略新契约的客户端或接口。

本计划没有周数承诺。当前已完成本地实现与大部分回归；CloudBase 迁移和部署等待 TCB_QcsRole 的 postgres:CreateAccount 权限。Desktop 1.2.0 构建和正式发布分别跟踪，尚未完成的项目仍按上述表格记录。
