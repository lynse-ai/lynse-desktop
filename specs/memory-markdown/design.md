# 通用专题 Markdown 设计

2026-10-24：需求已确认；用户明确要求“现在执行吧”，本轮直接实现并验证，不再增加阶段确认。范围为本地代码与验证，不部署或发布。

## 数据和处理

沿用现有 L1 memory_records 作为唯一事实存储。memory_file 只保存稳定文件 ID、标题、原名/别名、可选文件夹和专题 ID；memory_file_route/assignment 记录用户合并与拆分后的归属；memory_file_links 允许同一有依据的事实关联多个专题，不复制事实本体。自动事实按原始证据指纹去重，避免不同对象的同文陈述被全账号合并。使用现有按账号隔离的 knowledge 存储，不新增数据库表或权限。

原生 Wiki 的证据归类继续提供稳定专题 ID，新旧来源共同支持身份复用。课程、客户、投资标的等使用同一通用 topic，不增加行业枚举。发布事件带 topic_title；标题只作展示，不授予任何身份或作用域。文件稳定路径为 notes/topic-<id>.md，用户看到可读标题，不暴露内部路径。

提取任务收到专题、有效来源、已有文件与已有记忆，用于聚焦与去重。生成正文及内部章节按实际来源内容与语境选择语言，不限定中文、英文或混合；所有文件标题统一英文，正式英文名优先，无正式名称时使用罗马化，中文原名保留为别名。明确的产品命名词表独立于归类机制，用户已指定的“灵光记 = lynse”用于标题规范化，不参与身份或权限判断。正文专名和逐字引文保持原文；不把旧记忆当新证据。新增事实仍是需确认的候选，确认后进入同一文件和聊天记忆。用户拆分出的文件可被后续同一专题任务选择；只能选择输入中提供的文件 ID。

文件正文由有权限的已确认记录组成，段落间使用 Markdown 分隔线；候选内容作为文件内的待审阅更新。每条记录保留原始来源、性质、版本和更新时间。来源失效只移除其影响的内容。文件修订号覆盖元数据和所有实际成员，任一来源/内容/授权变化均使旧编辑失败。

编辑完整 Markdown 时，将文本差异映射回各原始记录，逐条走既有人工纠正机制；同一账号事务保证全部成功或回滚。跨来源分隔线的结构性编辑需要使用显式合并/拆分操作；删除内容通过既有冻结删除预览完成，避免绕过遗忘抑制机制。编辑标题可重命名，人工内容保留原语言。未确认内容不能通过保存文件直接变为已确认内容。

文件内容接近 6500 字符时，新增记忆分配到同专题的补充文件，保持每份文件不超过现有 8000 字符编辑上限；不预建空目录或行业模板。显式合并检查总长度，超限时引导使用文件夹。支持命名、移动、合并、按内容段拆分和删除。

文件写入操作回执仅保存路径和版本，重放重新读取当前授权，不能返回已删除内容。删除预览同时冻结受影响文件的关系与元数据，包含整份来源停止使用的间接影响；变化后必须重新预览，响应只返回相关文件路径，不把标题正文写进回执。前端请求继续使用令牌验证身份并在响应前后核对账号，查询和草稿按账号隔离。

## UI Design Specification

- Purpose: 直接查找和维护跨会议积累的专题记忆，不暴露内部状态分类。
- Direction: Industrial/utilitarian，沿用现有文件管理和文档阅读习惯。
- Palette: 项目现有语义 token；浅色参考 background #fafafa、foreground #202023、primary #5f67d8；暗色随现有主题。
- Typography: 现有 Inter / OPPO Sans；这是既有品牌约束，覆盖 UI 技能的默认字体/配色禁用建议。
- Layout: 左侧目录与文件列表，右侧文档；窄窗口列表/正文顺序展示。搜索、新建、刷新常驻，其他操作放入文件菜单。没有固定行业分类或状态标签栏。
- Content: 用户可见名称以 .md 呈现，文件标题英文，正文语言由内容决定；中文名称和原文引用可检索。确认、舍弃和删除预览留在文件内部。

## 验证

离线模拟多场景、跨会议增量、中文别名/英文文件标题/自适应正文语言、同名身份分离、候选隔离、源版本变化、CAS 冲突、人工修正、拆分合并、删除和回执重放。测试真实入口/令牌网关，界面类型检查、lint、单元测试、构建和本机合成数据浏览器操作。不开真实模型或外部业务 API。
