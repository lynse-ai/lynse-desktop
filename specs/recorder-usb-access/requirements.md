# 录音卡 USB 文件访问需求

目标是让用户插入录音卡后，通过桌面版的「USB 访问」开关取出和管理录音。用户已确认优先评估 Lynse 内访问。如果量产卡无法满足应用内接入条件，再评估系统文件管理器入口。

## 在 Lynse 内访问

1. 当用户第一次打开开关时，桌面端应识别匹配生产固件描述符的录音卡，并在设备鉴权成功后显示录音列表。没有卡片、存在多张卡片和鉴权失败时，应给出对应的连接状态。
2. 当用户选择一条或多条录音时，桌面端应支持逐条复制到用户指定的目录，并报告文件及批次进度。保存完成后应校验文件完整性。能进入现有录音导入流程的文件应具有桌面端支持的音频封装。
3. 当传输取消或连接中断时，桌面端应区分未完成文件和已保存文件。重连后只有在确认是同一设备、同一份录音及同一段有效的连续数据时，才使用原有偏移续传。
4. 当用户明确确认删除卡片原件且卡片返回成功时，桌面端应刷新设备列表。复制或导入时应保留卡片原件。
5. 开关默认关闭。当用户关闭开关时，桌面端应停止接收新任务，结束传输并释放 USB 接口。USB 连接和保存到本地目录应可独立于云上传运行。

SDK V1.0.0 提供 `connect`、`getFileList`、`downloadFile`、`stopTransfer` 和 `deleteFile`。卡片内重命名、移动和电脑写回需要固件另外提供文件操作。SDK 当前以 `Uint8Array` 返回下载数据，长录音需要验证内存占用和断点行为。

## 在系统文件管理器访问

1. 当用户开启开关且固件进入 USB 大容量存储模式时，系统应在访达或资源管理器中挂载录音卷，用户可直接复制录音。
2. 在存储卷挂载期间，固件应保证主机访问和卡片端录制、索引更新之间的数据一致性。若支持写入，需明确允许的目录和文件操作，并验证断线后的索引恢复。
3. 当用户关闭开关时，应先处理系统弹出，再由固件恢复原有模式。若切换后设备以新的 USB 接口重新枚举，须验证切回所用的控制通道。

当前 SDK 公开接口没有大容量存储模式开关。`custom` 可以承载厂商已有的指令，需由硬件方确认生产固件的支持情况。

## 实机验证前需要的资料

- 量产型号、固件版本、实际 VID/PID 和测试设备。连接口令随对应固件通过安全渠道提供。
- 应用内路径需要确认量产固件的原生 USB 访问、Windows 端 WinUSB 绑定，以及下载数据的容器、编码和校验值含义。需要实际录音覆盖读取、保存、播放和中断续传。原生 SDK 或正式 USB 协议可用于后续生产接入。
- 系统文件管理器路径需要确认 MSC 模式及切换指令、切换前后的 USB 描述符、可写范围、安全弹出和切回方式。

本机测试确认 macOS WKWebView 在安全上下文中仍未暴露 WebUSB。原生 USB 枚举和 SDK 兼容层的验证结果见 [技术评估](design.md)。实际卡片尚未连接，设备鉴权、音频格式和 Windows 驱动绑定待实机验证。
